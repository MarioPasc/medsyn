# ccDDPM Output Structure Reference

This document describes the complete output structure generated by the ccDDPM (Class-Conditioned Denoising Diffusion Probabilistic Model) training and generation processes.

## Training Outputs

### Base Directory
The base output directory is controlled by the configuration parameter:
- **Config path**: `ccddpm.train.output_dir`
- **Default value**: `./outputs/ccddpm`
- **CLI override**: `--outdir /path/to/output`

### Directory Structure

```
outputs/ccddpm/                          # Main output directory
├── training_metrics.csv                 # Detailed epoch-level metrics (primary log)
├── train_log.csv                        # Simple step-level log (backward compatibility)
├── ckpts/                               # Model checkpoints directory
│   ├── best.pt                          # Best model (lowest validation loss)
│   ├── last.pt                          # Most recent epoch checkpoint
│   └── epoch_XXXX.pt                    # Periodic checkpoints (every N epochs)
└── samples/                             # Training visualization images
    ├── epoch_XXXX_recon.png             # Reconstruction comparisons (saved every epoch)
    ├── epoch_XXXX_noising.png           # Forward noising process (every 10 epochs)
    ├── epoch_XXXX_denoising.png         # Reverse denoising process (every 10 epochs)
    ├── epoch_XXXX_multistep.png         # Multi-timestep reconstructions (every 10 epochs)
    └── epoch_XXXX_classes.png           # Class-conditional samples (every 10 epochs)
```

## File Descriptions

### CSV Logs

#### `training_metrics.csv` (Primary Log)
**Purpose**: Comprehensive epoch-level training and validation metrics.

**Frequency**: One row per epoch per split (train/val).

**Fields**:
- **Basic Info**:
  - `epoch`: Epoch number
  - `split`: Dataset split ('train', 'val', or 'test')
  - `time_s`: Timestamp
  - `lr`: Learning rate
  
- **Loss Metrics**:
  - `loss`: Mean loss across batches
  - `loss_std`: Standard deviation of loss
  - `loss_c0`, `loss_c1`, ..., `loss_cN`: Per-class losses
  
- **Reconstruction Quality** (computed on denoised samples):
  - `psnr`: Peak Signal-to-Noise Ratio (dB)
  - `ssim`: Structural Similarity Index
  
- **Noise Prediction Quality**:
  - `noise_mse`: Mean Squared Error between predicted and true noise
  - `noise_mae`: Mean Absolute Error between predicted and true noise
  
- **Model Health**:
  - `grad_norm`: Gradient norm (for training only)
  - `ema_enabled`: Whether EMA (Exponential Moving Average) is active
  
- **Statistics**:
  - `total_count`: Total samples processed in the epoch

**Example**:
```csv
epoch,split,time_s,lr,loss,loss_std,psnr,ssim,noise_mse,noise_mae,grad_norm,ema_enabled,total_count,loss_c0,loss_c1,...
1,train,1729200000.0,0.0002,0.1234,0.0567,28.45,0.8234,0.0123,0.0567,1.234,1.0,12800,0.1123,0.1345,...
1,val,1729200000.0,0.0002,0.1189,0.0534,29.12,0.8456,0.0118,0.0543,0.0,1.0,3200,0.1078,0.1290,...
```

#### `train_log.csv` (Backward Compatibility)
**Purpose**: Simple step-level training log.

**Frequency**: Every `log_every` steps (default: 100).

**Fields**:
- `epoch`: Current epoch
- `step`: Global training step
- `loss`: Batch loss
- `lr`: Learning rate
- `time_s`: Elapsed time since epoch start

### Checkpoint Files (`ckpts/`)

All checkpoints are saved as PyTorch `.pt` files with the following structure:

```python
{
    "model": model.state_dict(),           # Model weights
    "opt": optimizer.state_dict(),         # Optimizer state
    "epoch": int,                          # Epoch number
    "val_loss": float,                     # Validation loss at this epoch
    "ema": dict or None,                   # EMA shadow parameters (if enabled)
    "cfg": dict                            # Training configuration
}
```

#### `best.pt`
- **Purpose**: Model with the lowest validation loss
- **Updated**: Whenever validation loss improves
- **Recommended**: Use this for inference/generation

#### `last.pt`
- **Purpose**: Most recent epoch checkpoint
- **Updated**: Every epoch
- **Use case**: Resume training or use final model regardless of validation performance

#### `epoch_XXXX.pt`
- **Purpose**: Periodic snapshots during training
- **Frequency**: Controlled by `ccddpm.train.ckpt_every_epochs` (default: every epoch)
- **Use case**: Track model evolution, resume from specific epochs

### Visualization Images (`samples/`)

All images are saved as PNG files with pixel values in [0, 1] range.

#### `epoch_XXXX_recon.png` (Every Epoch)
**Content**: Reconstruction quality comparison
- **Layout**: 3 columns per sample (Original | Noisy | Reconstructed)
- **Samples**: Up to 5 validation images
- **Purpose**: Monitor denoising quality during training

**Example layout** (5 samples × 3 columns = 15 images):
```
[Original_1] [Noisy_1] [Recon_1]
[Original_2] [Noisy_2] [Recon_2]
[Original_3] [Noisy_3] [Recon_3]
[Original_4] [Noisy_4] [Recon_4]
[Original_5] [Noisy_5] [Recon_5]
```

#### `epoch_XXXX_noising.png` (Every 10 Epochs)
**Content**: Forward noising process visualization
- **Layout**: 11 timesteps showing progressive noise addition
- **Timesteps**: t=0 (clean) → t=T (pure noise)
- **Purpose**: Visualize how the diffusion process adds noise

**Example layout**:
```
[t=0] [t=100] [t=200] [t=300] ... [t=1000]
```

#### `epoch_XXXX_denoising.png` (Every 10 Epochs)
**Content**: Reverse denoising process (full DDPM sampling)
- **Layout**: 11 timesteps showing progressive denoising
- **Timesteps**: Pure noise → Final generated image
- **Purpose**: Monitor generation quality

**Example layout**:
```
[Pure Noise] [t=900] [t=800] ... [t=0 Clean]
```

#### `epoch_XXXX_multistep.png` (Every 10 Epochs)
**Content**: Reconstruction quality at different noise levels
- **Layout**: Original + 6 reconstructions at different timesteps
- **Timesteps**: [50, 150, 300, 500, 700, 900]
- **Purpose**: Assess model's ability to reconstruct from various noise levels

**Example layout**:
```
[Original] [t=50] [t=150] [t=300] [t=500] [t=700] [t=900]
```

#### `epoch_XXXX_classes.png` (Every 10 Epochs)
**Content**: One sample per class
- **Layout**: One row with `num_classes` samples
- **Purpose**: Verify class-conditional generation quality

**Example layout** (9 classes):
```
[Class_0] [Class_1] [Class_2] [Class_3] [Class_4] [Class_5] [Class_6] [Class_7] [Class_8]
```

## Generation (Inference) Outputs

### Base Directory
The base output directory is controlled by:
- **Config path**: `ccddpm.infer.out_dir`
- **Default value**: `./samples/ccddpm`

### Directory Structure

```
samples/ccddpm/                          # Inference output directory
├── class_0/                             # Generated samples for class 0
│   ├── class00_00000.png
│   ├── class00_00001.png
│   ├── ...
│   └── _grid_step0.png                  # Optional grid visualization
├── class_1/                             # Generated samples for class 1
│   ├── class01_00000.png
│   ├── class01_00001.png
│   └── ...
└── class_N/                             # Generated samples for class N
    └── ...
```

### File Naming Convention

#### Individual Images
Format: `classXX_YYYYY.png`
- `XX`: Zero-padded class ID (e.g., `00`, `01`, `08`)
- `YYYYY`: Zero-padded sample index (e.g., `00000`, `00123`)

#### Grid Images (Optional)
Format: `_grid_stepY.png`
- Created when `ccddpm.infer.save_grid = true`
- `Y`: Batch step number
- Contains a grid of all samples from that batch

## Configuration Parameters

### Training Output Control

```yaml
ccddpm:
  train:
    output_dir: ./outputs/ccddpm        # Base output directory
    ckpt_every_epochs: 1                # Checkpoint saving frequency
    log_every: 100                      # Step-level logging frequency
    patience: 15                        # Early stopping patience (epochs)
    use_tqdm: true                      # Enable/disable progress bars
```

### Inference Output Control

```yaml
ccddpm:
  infer:
    out_dir: ./samples/ccddpm           # Generation output directory
    save_grid: true                     # Save grid visualizations
    guidance_scale: 0.0                 # Classifier-free guidance scale
    num_inference_steps: 1000           # Number of denoising steps
```

## Early Stopping

The training process implements early stopping:
- **Metric**: Validation loss
- **Patience**: Configurable via `ccddpm.train.patience` (default: 15 epochs)
- **Behavior**: Training stops if validation loss doesn't improve for N consecutive epochs
- **Best Model**: Always saved to `ckpts/best.pt`

When early stopping triggers, you'll see a summary:
```
================================================================================
⚠ Early Stopping at Epoch 35
================================================================================
No improvement in validation loss for 15 consecutive epochs.
Best model saved at epoch 20 with val_loss=0.0876
================================================================================
```

## HPC/SLURM Integration

### Result Synchronization

The `picasso_sbatch.sh` script searches for outputs in this priority order:

1. **CLI-specified output directory** (`--outdir`)
2. **Config default**: `./outputs/ccddpm`
3. **Alternative paths**: `./outputs`, `./samples/ccddpm`, etc.

The script identifies ccDDPM outputs by looking for:
- `ckpts/` directory
- `samples/` directory
- `training_metrics.csv` file
- `class_X/` directories (for generation outputs)

### Recommended Settings for HPC

For cleaner HPC logs, disable tqdm progress bars:

```yaml
ccddpm:
  train:
    use_tqdm: false    # Disable interactive progress bars
```

This prevents cluttered log files while maintaining all other logging functionality via the CSV files and periodic console output.

## Troubleshooting

### "No output directories found"
Check these locations in order:
1. Value passed to `--outdir` CLI flag
2. `ccddpm.train.output_dir` in your YAML config
3. Default: `./outputs/ccddpm` relative to where the script runs

### "Checkpoint file not found"
Verify the checkpoint path in your config is absolute:
```yaml
generate:
  checkpoint: /absolute/path/to/ckpts/best.pt  # Must be absolute
```

### "Missing visualizations"
- Reconstruction images: Generated every epoch
- Detailed visualizations: Only generated every 10 epochs (or epoch 1)
- Check `use_tqdm` setting if progress indicators are missing
